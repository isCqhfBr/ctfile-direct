========================================================
城通网盘 多账号加速下载器    使用说明
========================================================
安装位置：与「城通网盘下载器.exe」同一目录
更新：2026-10-05（原生 EXE 界面版）

--------------------------------------------------------
怎么用（三步）
--------------------------------------------------------
1) 双击「城通网盘下载器.exe」
2) 把城通分享链接粘到「① 分享链接」框里，点「解析」
3) 点「开始下载」

就完了。解析后会看到每个账号各分到几条线程、合计多少并发。
下载完会弹出提示，可以直接跳到文件所在位置。

小技巧：
  · 把分享链接直接拖到 exe 文件上，界面会自动打开并开始解析
  · 解析出来的主直链不放心的话，也可以自己复制去 IDM / 迅雷

--------------------------------------------------------
界面说明
--------------------------------------------------------
① 分享链接    支持 https://url91.ctfile.com/f/xxx?p=提取码 这种带提取码的链接，
              也支持只填分享码（37476991-1447877437-0eb71b）
② 下载来源    列出每个账号/匿名槽分到的线程数和主机，合计就是总并发数
   保存目录   默认「下载」文件夹，可改；右边两个按钮是选目录 / 打开目录
   进度条     下载时显示百分比、速度、剩余时间
③ 账号池     每个免费账号提供 2 个线程。加一个账号 = 多 2 线程。
              密码错误的账号会自动跳过，不影响其他账号。
              勾选「额外使用匿名通道」再多 1 线程（不需要账号）。

--------------------------------------------------------
实测数据（同一台机器、同一个 13.5MB 文件）
--------------------------------------------------------
    来源组合            线程   耗时        平均速度
    匿名                1      --          ~100KB/s
    1 个账号            2      50.2s       275KB/s
    2 账号 + 匿名        5      7.9s        1.72MB/s     ← 约 6 倍

为什么能加速：城通的并发配额是**按账号**算的，而且账号之间**相加**。
实测：同一账号开 4 条独立直链只有 2 条通；换 2 个账号各 2 条 → 4/4 全通。

--------------------------------------------------------
遇到「HTTP 429 请求过于频繁」怎么办
--------------------------------------------------------
这是城通按 IP 做的限流，**不是链接失效，也不是工具坏了**。

触发原因：短时间解析了大量链接（比如批量探测几百个分享链接）。
处理办法：等 10~30 分钟自动恢复，什么都不用改。

工具已经内置了 2 秒 / 5 秒两次自动退避重试；仍然失败才会弹中文提示。
想让它恢复快一点：换个网络（手机热点）、或者重启光猫换个 IP。

（实测：限流是按接口主机分开算的。被限时 api.ctfile.com 正常、
webapi.ctfile.com 和 rest.ctfile.com 返 429，恢复也是一个个先后恢复。）

--------------------------------------------------------
⚠️ 风险提示
--------------------------------------------------------
城通风控专门盯「同一 IP 多账号下载同一文件」这个模式，一旦判定就会把账号
锁死（登录返回 401「多用户登录被锁定，请联系客服」）——之前有个共享号就是
这么被封的。账号越多、下载越频繁，被一起封的概率越高。
建议只用自己的号，别为了加速去注册一堆小号。

密码以明文保存在同目录的 config.json 里（仅本程序读取）。
删掉 config.json 就会退回「匿名单线程」模式。

--------------------------------------------------------
命令行用法（可选，方便脚本调用）
--------------------------------------------------------
exe 自带命令行模式，不进界面直接干活：

  城通网盘下载器.exe --cli "分享链接"
  城通网盘下载器.exe --cli "分享链接" --out "D:\存哪" --no-download

  --out <目录>     指定保存目录（默认「下载」文件夹）
  --no-download    只解析拿直链，不下载

另外还有一套 Node 脚本版（需要 DSH 自带的 node 运行时）：
  cli\解析直链.bat     双击→粘贴链接→可选下载（和 exe 共用 config.json）
  cli\resolve.mjs      只解析直链
  cli\下载.mjs         多来源并发下载

--------------------------------------------------------
技术备注（想改代码的看这里）
--------------------------------------------------------
解析链路（每个账号各走一遍）：
  1. GET  webapi.ctfile.com/getfile.php?path=f&f=<分享码>&passcode=<提取码>
          → 拿到 file_id / file_chk / xtredirect 等
  2. POST api.ctfile.com/v4/user/auth/login   {email, password} → token
  3. xtlink = "ctfile://" + xtredirect
     POST rest.ctfile.com/p2/browser/file/list      {xtlink, token, reload:false} → file key
     POST rest.ctfile.com/p2/browser/file/fetch_url {xtlink, file_id:key, token} → limit=2 直链
  4. 匿名槽：GET webapi.ctfile.com/get_down_url.php?uid&fid&file_chk&start_time&wait_seconds&rd → limit=1

下载：把所有来源按各自 limit 展开成 worker 表，文件按 worker 总数等分，
每段用 HTTP Range 拉取，用 RandomAccess.WriteAsync 按偏移直接写进同一个文件，
不需要合并临时分片。

踩过的坑：
  · 老的 rest.ctfile.com/p2/user/auth/login 已废弃（410 请升级客户端），
    GitHub 上 nekohy/ctfile-downloader 那套拿 token 的方法已经不能用了
  · xtlink 必须是 xtredirect，直接拿 uid-fid-chk 当 xtlink 会报「找不到小通链接」
  · token 有效期只有 15 分钟，所以每次运行都重新登录
  · fetch_url 传 thread/limit/max_thread 参数一律无效，线程数服务端说了算
  · 直链里 limit=1 时开多连接会被 503 拒绝；limit=2 就最多 2 条

重新编译：
  cd src
  dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o ..\dist

  产物是「依赖 .NET 8 桌面运行时」的小体积单文件（约 200KB）。
  本机已装 .NET 8 SDK（含桌面运行时），所以直接能跑；
  如果要拿到没装 .NET 的机器上用，把 --self-contained 改成 true
  （体积会变成 100MB+）。
